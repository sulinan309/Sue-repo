# 攀岩动作标注 demo

对攀岩视频做逐帧动作标注：姿态骨架、岩点、接触判定、动作阶段和 2D 质心代理，
输出带覆盖层的视频和逐帧证据记录。

这是 [`climbing-kb/docs/03-感知层架构.md`](../climbing-kb/docs/03-感知层架构.md)
里 P0–P3 档的一个可运行实现。

---

## 跑起来

```bash
pip install -r requirements.txt
./get_model.sh                       # 下载姿态模型，约 9.4MB
python3 annotate.py 你的视频.mp4 -o out
```

产出：

| 文件 | 内容 |
| --- | --- |
| `out/annotated.mp4` | 带覆盖层的视频 |
| `out/evidence.jsonl` | 逐帧证据记录，每行一帧 |
| `out/summary.json` | 汇总 + 与知识库的能力对照 |
| `out/holds.json` | 检测到的岩点（参考帧坐标） |

常用参数：

```bash
--ref-frame N     用哪一帧作为岩点参考帧（默认 0）
--samples N       岩点检测的采样帧数（默认 14）
--persist F       岩点位置一致性阈值（默认 0.4）
--no-video        只跑分析不渲染视频
```

两段测试素材上的表现（纯 CPU）：

| | 素材 A（207 帧 / 6.9s） | 素材 B（999 帧 / 33.3s） |
| --- | --- | --- |
| 姿态检出率 | 86.5% | 83.7% |
| 平均接触点 | 3.7 / 4 | 3.07 / 4 |
| 稳定岩点 | 27 | 17 |
| 岩点关联率 | 0.71 | 0.24 |
| 相机漂移补偿 | 53px | 8.6px |
| 耗时 | 20s | 123s |

素材 B 的岩点关联率只有 0.24——那面墙是橙色岩点配橙色墙，还有白色岩点，
颜色分割大量漏检。**但接触判定仍然准确**，因为接触不依赖岩点检测。
这是上面第二条设计取舍的直接验证。

## 它做了什么

```
姿态流 ──┐
        ├──→ 接触代理 ──→ 动作阶段 ──→ 证据记录 ──→ 覆盖渲染
视觉流 ──┘
```

### 姿态流（`climbanno/pose.py`）

MediaPipe 33 点，**ROI 追踪**：用上一帧的人体框外扩、上采样再检测。
攀岩视频里人常常只占画面一小块，整帧送检检出率很低——
在测试素材上，这一招把检出率从 46.7% 提到 92.9%。

**重捕获策略是检出率的关键，比换模型重要得多。**
第一版在检测失败时把 ROI 直接置空、下一帧回退到全图原分辨率检测。
人只占画幅 1/5 时，缩到模型输入尺寸就太小了，于是
「一次丢失 → 全图检测失败 → 继续丢失」形成连锁：
实测开头 20% 的检出率只有 43.7%，而一旦锁定，后 60% 是 100%。

改成丢失后保留最后已知位置、按 1.6x → 2.6x → 全图 逐级扩大搜索，
每级都上采样后再送检；再加一趟用前后成功帧插值 ROI 的补检
（人是连续运动的，夹在两个成功帧之间的失败帧位置约束得很好）。

结果：**83.7% → 100%，而且更快**（89s vs 123s）——
不再反复做昂贵的全图检测。换模型一分钱没花，改的全是调度逻辑。

同时算出环节质量加权的 **2D 质心代理**（Winter / de Leva 人体测量数据）。
注意这是投影到图像平面的二维代理，不是三维重心。

### 视觉流（`climbanno/holds.py`）

岩点检测用颜色分割（深色 + 高饱和），加形状过滤。

两个关键设计：

**一、人体掩膜只遮核心，不遮手脚。**
第一版把姿态凸包整体挖掉，结果接触判定全部失败——
因为**接触中的岩点必然紧贴肢端**，遮住肢端就正好丢掉最需要的那些岩点。
现在只遮头和躯干核心（头永远不是接触点，深色头发却很容易被当成岩点）。

**二、用时间一致性剔除假阳性。**
代价是鞋子和深色衣物会进候选。解法利用了一个事实：
**岩点不动，鞋子和衣服会动。**
多帧检测后用单应把候选点映射回参考帧坐标，同一个岩点会聚成一簇，
人身上的假阳性因为人在移动是散的，聚不起来。只保留出现率达标的簇。

### 墙面锁定

用墙面特征逐帧估单应，把岩点位置锁在墙上。
测试素材相机有 ~53px 手持漂移，补偿后岩点全程贴合。

这是 P4「墙体坐标系」的一个**极简版本**：只做二维图像对齐，
没有度量尺度也不知道墙面法向。它能稳定岩点位置，
但回答不了「髋部离墙多远」——那需要真正的墙面几何。

### 接触代理（`climbanno/contact.py`）

两个设计取舍，都是踩过坑之后改的。

**一、速度在墙面坐标里算，不在图像坐标里算。**
手持镜头会让静止的肢体在图像上也有速度，静止判定跟着失效。
用单应把肢端映射回参考帧坐标之后，相机运动被消掉，速度才是身体真实的速度。

**二、接触主要由「墙面坐标里的静止」判定，岩点关联只是附加信息。**
第一版把「找得到岩点」当成接触的必要条件，结果岩点漏检就变成漏判接触——
白色岩点、与墙同色的岩点都会漏。
反过来想：**肢端在墙面上静止不动，本身就是接触的证据**，
哪怕我们没认出它踩的是哪个点。所以现在岩点关联不上也照样判接触，
只是标签上不显示是哪个点。

| 状态 | 条件 |
| --- | --- |
| 接触 | 墙面坐标速度 < 0.42 躯干长/秒，连续 3 帧 |
| 移动 | 速度 > 0.85 躯干长/秒 |
| 不确定 | 其余 |

岩点关联：肢端到岩点**边缘**（不是质心）距离 < 0.30 躯干长。
用质心距离会把大体积块上的真实接触判成未接触。

动作阶段：接触稳定 / 单肢转移 / 多肢过渡 / 接触点不足，众数平滑防跳变。

### 覆盖设计（`climbanno/render.py`）

一条原则：**画面上每一个元素都要挣得它占的位置。**

第一版把检测到的 27 个岩点全部圈出并编号，画面被编号淹没，
真正重要的四个接触点反而看不出来。现在只画与判定直接相关的东西：

| 元素 | 含义 |
| --- | --- |
| 绿色粗骨架 | 姿态流观察 |
| 绿环 + 标签 | 该肢端判定为接触 |
| 蓝色准星 ①② | **接下来的两个落点**（回放已知，非预测） |
| 半透明绿面 | **支撑面**——接触点围出的范围（`PHY-EQUILIBRIUM-002`） |
| 品红点 | 2D 质心代理 |

检测到的岩点全部保留在 `holds.json` 里，一个都不画在画面上。

### 落点提示是回放，不是预测

「接下来的两个落点」是**从记录里向前看**，取接下来两次肢体移动的实际落点，
用墙面单应投影到当前帧。

**这不是预测。** 真正的预测要知道线路上有哪些点、哪些属于这条线，
那需要岩馆线路底库，视频本身给不出。
在攀爬回放这个场景里「已知未来」是成立的，但文案必须说清楚是回放而不是实时指路——
覆盖层底部固定写着「落点为回放已知的实际落点，非实时预测」。

落点已经到达（与当前肢端距离小于标记半径）时不再提示。

### 姿态状态识别（`climbanno/posture.py`）

身体朝向 × 手臂状态的四格：

| | 至少一条直臂 | 双肘同时弯曲 |
| --- | --- | --- |
| **正身** | 正身支撑 | 正身拉臂 |
| **侧身** | 侧身省力 | 侧身未省力 |

朝向怎么测：相机在攀爬者身后时，正对墙面的肩线与相机视轴垂直、投影最宽；
转髋侧身时肩线转向视轴方向、投影缩短。
所以 `肩宽/躯干长` 相对该段视频自身的 90 分位值就是朝向代理——
用视频自身归一而不是固定常数，因为不同人的肩宽/躯干比本来就不同。

**边界：识别的是姿态组合，不是发力。**
单目视频测不到握力、蹬力和肌肉激活。「侧身未省力」的意思是
「已经侧身但两臂仍屈着」，是可观察的姿态事实，不是对发力效率的测量。
状态名里没有「乏力」「发力」这类词，就是这个原因。

支撑面是这一版新加的。它把知识库里最抽象的一条物理原理——
「重心的投影落在支撑范围内，身体才能不靠拉力保持静止」——变成看得见的东西。
`evidence.jsonl` 里记了 `com_in_support` 字段，但**只作为二维投影代理**，
不当作力学稳定性判断：真正的判断需要墙面法向和重力方向，那是 P4 的事。

## 边界声明

这是整个 demo 最要紧的部分。

**所有接触状态都是二维视觉邻近代理，不是力学接触。**
「已确认」只表示肢端与岩点在图像上足够近且足够稳，**不表示这只手在承重**。

明确未测量的量：

- 接触力与各接触点的负荷分配
- 摩擦系数与鞋底状态
- 重心的三维位置（只给二维投影代理）
- 髋部到墙面的度量距离（需要墙体坐标系）
- 鞋踩在岩点有效受力面还是边缘（需要接触区精细视觉）

覆盖层底部固定保留一行「未测量」声明。这不是免责声明，是产品纪律：
知识库规范 05 节要求表达强度随证据等级变化，看不准就说看不准。

**本管线只输出证据，不输出教学建议。** 建议由知识库和攀岩专家模型负责——
这条分工是刻意的：证据可以被验证，建议需要被审核，两者不该混在一层。

## 从证据到候选发现

```bash
python3 review.py out2/evidence.jsonl
```

`review.py` 是「证据 → 候选发现」的接缝，**不产出教学建议**——
建议归知识库和攀岩专家模型。

**每条候选发现都必须过基线对比。** 这是这个文件存在的主要理由：
攀岩视频里很多量天然高频（髋部 30% 的帧在动、手部 78% 的帧附近有移动），
不跟随机基线比，很容易把「本来就常见」当成「这个人的问题」。

一条没过基线的观察，不是弱发现，**是不是发现**。

`review.py` 出两组指标：

**时序类**（髋先动、脚脱落同步、停顿）——每条过基线对比。
**姿态几何类**（双肘弯曲、站姿宽度、重心水平位置），按上攀/下攀分段。

> **一条教训**：第一版只算了时序类，结论是「可测层看不到问题」——**那是错的**。
> 屈臂、站姿宽度、重心水平位置全是纯 2D 姿态，同样在 P0/P1 档，
> 而且屈臂在知识库里有 4 处 observables 明确要求
> （`PRIN-LEGS-004`、`FAULT-PULL-FIRST-011`、`FAULT-SQUARE-REACH-008`、
> `TEC-POS-ORIENT-002`），还有两个物理单元撑腰。
> 漏算不是能力不足，是**没去算知识库已经写明要看的东西**。
>
> 归一化基准要用**躯干长**不用肩宽：侧身时肩线在二维投影里会坍缩，
> 用肩宽做分母会得到虚高的「宽站姿」占比。

时序类在 33 秒素材上两条候选都没有通过：

| 候选 | 观察 | 基线 | p | 判定 |
| --- | --- | --- | --- | --- |
| 伸手前髋已先动 | 15/20 (75%) | 57% | 0.052 | 样本不足，仅为倾向 |
| 脚脱落与伸手同步 | 12/17 (71%) | **78%** | 0.769 | 与基线无差异，不构成发现 |

第二条尤其能说明问题：71% 看起来很高，但基线是 78%——
不做基线对比就会把它报成一条发现。

## 与知识库的连接

`climbanno/kb_link.py` 对照 `climbing-kb` 的 122 条 observables，
回答一句话：**这段视频跑完，知识库里哪些「视频中能看见什么」是这条管线真的能给出的？**

当前 8 条，全部经过校验确认在知识库中逐字存在：

| 知识单元 | observable |
| --- | --- |
| `PRIN-SPEED-005` | 是否出现长时间停顿后才启动（犹豫） |
| `FAULT-HESITATE-013` | 单次停顿的时长和全程停顿总时长 |
| `FAULT-REACH-FIRST-005` | 伸手动作与髋部移动的先后顺序 |
| `TEC-POS-COM-001` | 髋部在伸手之前有没有先移动 |
| `PRIN-COM-003` | 髋部的移动路径 |
| `FAULT-WRONG-HAND-015` | 是否出现同一个岩点上的换手动作 |
| `TEC-POS-TENSION-003` | 伸手的瞬间脚是否脱落 |
| `FAULT-FOOT-CUT-003` | 脚脱落与伸手动作之间的时间关系 |

没有这一层，标注只是好看的覆盖层；有了它，标注才是知识库的证据来源。

## 已知限制

- **颜色阈值是针对「浅色墙 + 深色/饱和色岩点」调的**，换岩馆需要重标。
  真实产品应当用岩馆标准 Beta 建线路底库，而不是靠颜色现场猜。
- **不区分线路。** 检测的是画面里所有岩点，不是某一条线路的岩点——
  颜色分割能「找出岩点」，不能「找出这条线的岩点」。
  线路归属得靠岩馆的线路底库，视频本身给不出。
  现在只画接触中的岩点，所以这个缺口在画面上不明显，但它仍然在。
- **单人。** `num_poses=1`，画面里有其他人会干扰。
- **姿态检出率 86.5%**，遮挡和运动模糊时会丢帧。丢帧不插值——看不见就是看不见。
- **右脚在大体积块上常判为「可能」而非「已确认」**，因为脚尖关键点与
  大岩点的几何关系不稳定。这是 P3 未完成部分的一个具体例子。
