## 这份文件是什么

知识库里所有单元的 `review.status` 都停在 `pending`。
按 `project/02-决策记录.md` 的 **D-003**，项目已决定暂不引入外部真人攀岩专家，
所以这个队列**会长期堆积**——这是已知的、被接受的代价，不是疏漏。

既然会堆积，这份文件就必须写成**可以直接照着答**的样子：
每条问题都给出「我们现在是怎么写的、依据是什么、你答 A 我们改什么、答 B 我们改什么」。
一句「请确认是否正确」在一个月后没有人答得动。

**它不重复整库的复核清单。** 70 个单元全部待复核这件事记在
`project/01-任务看板.md` 的「待复核」一栏。这里只收**具体的、有分歧或没有依据的点**。

## 怎么回答

在每条问题下面直接追加一段：

```
**答**（姓名 / 攀岩年限或教练资质 / 日期）：
你的答案，以及如果可能，一句「为什么」。
```

不需要改任何 YAML，不需要跑任何脚本。研究专家会据此改单元、升版本、
并把 `review.climb` 填上你的名字。

**注意**：`review.status` 只有人能置为 `climb_reviewed` 或 `approved`。
研究专家 agent 无论如何都只能停在 `pending`。

## 回答的证据强度

如果你的答案属于下面哪一类，请顺手标一下，我们要据此定证据等级：

- **我教这个动作时就是这么教的** → 专家共识
- **我见过，但也见过相反的做法** → 请把两种都写下来，我们并列记录，不调和
- **我不确定** → 直接说不确定，它会变成「证据不足」，产品会停止推断

### Q-A1-01 · 仰角上换脚，还需不需要「先把重心移到留守脚上方」？

**影响**：`TEC-CON-SWAP-003` 的 `phases.prepare`、第一条 hint、
`TASK-FOOT-TAP-021` 的适用范围。这是本轮最要紧的一条。

**背景**：
我们写「换脚之前先把重量挪到留守脚那一侧」，依据是一个力矩关系——
重心到留守脚的水平距离趋近 0 时，旧脚离开产生的力矩也趋近 0。
在直墙上这个推理很直接。

但检索到一篇研究（Noé F. 2006, J Electromyogr Kinesiol 16(4):336-41，
**来源状态为候选：本环境打不开原文，只核到搜索返回的二手摘要**）说：
同样是在攀岩姿势下释放一条腿，**直墙上动作前有预期性姿势调整（APA），
仰角上没有**，作者把仰角上 APA 的消失解释为该姿势下本来就能产生足够的冲量。

**问题**（请选一个，或写第四种）：

- **(a)** 仰角上同样要求先移重心，只是幅度更小、更不容易看出来；
- **(b)** 仰角上机制不同：靠的是先收紧核心把髋拉向墙面，而不是水平移动重心，
  提示应当整条换掉；
- **(c)** 看脚点和角度而定——如果是这样，请说一句**你判断时看的是什么**；
- **(d)** 其他。

**我们现在的写法**（原文）：

> `prepare`：先决定换哪只脚……再把重心移向将要留下的那个支撑，
> 把要走的那只脚卸载到能轻轻抬起来为止。

以及场景三里写着：仰角上「没看到重心先移动」**不能**作为判错的依据。

**你答 (a)**：保留现有写法，在仰角一节补一句「幅度更小」。
**你答 (b)**：`phases.prepare` 按墙角拆成两套操作（像 `TEC-CON-LOAD-002`
对板墙/仰角那样拆），hint 增加一条仰角专用的；这是结论变更，
单元升主版本并退回重新审核。
**你答 (c)**：把你的判断依据写成 `applies_to` / `not_applicable` 的条件。

### Q-A1-02 · 三种换脚做法的中文名和适用条件

**影响**：`TEC-CON-SWAP-003` 的「三种常见做法」表，以及术语表 `kb/glossary.yaml`。

**背景**：我们从多个岩馆与教学站点的搜索摘要里归纳出三种做法，
**一页原文都没打开**（出站策略拦截），中文名是我们自己的译法：

| 我们叫它 | 英文 | 我们写的做法 |
| --- | --- | --- |
| 叠脚换 | toe-on-toe | 新脚轻轻放在旧脚上面，把下面那只脚抽出来 |
| 小跳换 | hop swap | 新脚大脚趾对准旧脚正上方，轻跳一下完成交换 |
| 转脚换 | pivot | 一只脚从脚点侧面滚下去，另一只脚从侧面滑进空位 |

**问题**：

1. 国内岩馆通常管这三种叫什么？（我们会把你的说法设为主名称，
   现在的译法降为别名——术语约定是「以国内商业岩馆的日常说法为准」。）
2. 除这三种，还有别的常用做法吗？
3. **教新手时的推荐顺序是什么？先教哪一种？**
4. 每一种在什么脚点上**不该用**？

**你答完之后我们改**：这张表的表头与「适用」列、`aliases` 字段、
以及可能新增的 `not_applicable` 条目。

### Q-A1-03 · 抬脚自测（`TASK-FOOT-TAP-021`）在真实教学里站不站得住？

**背景**：这个任务要求用户在换脚之前，先把要换掉的那只脚

它是从力矩关系推出来的一个二值判据，**没有任何教学来源，也没有在用户身上验证过**。

**问题**：

3. 直墙和板墙之外，仰角上要不要直接禁用？（与 Q-A1-01 相关）
4. 如果你会用一个不同的自测来判断「重量挪到位了没有」，那是什么？

**你答完之后我们改**：`steps`、`grade_range`、`safety`；
若答案是「会诱导多停留」，任务改成只在**练习课**里做、不进产品提示。

### Q-A1-05 · 「换脚就掉」的六个候选解释，频率顺序对吗？漏了什么？

**影响**：`FAULT-SWAP-DROP-021` 的候选解释顺序。
**这个顺序会决定产品先问用户哪一个问题**，所以它不是排版问题。

**背景**：六条候选解释是从库内已有的物理和技巧单元推演出来的，
**没有一条有直接研究支撑，也没有真实失败案例验证过**：

1. 交接前重心还在旧脚一侧，旧脚一走就被力矩转开
2. 交接期间双脚同时离点，体重全上手
3. 新脚落点不准，落上去还要挪
4. 新脚落位了但没加载，重量始终没交出去
5. 这一步根本不该换脚，用旗式成本更低
6. 换过去的脚踩的角度不对，站住了但转不动，被误说成「支撑不住」

**问题**：

1. 请按**在新手身上出现的频率**重排这六条。
2. 漏了什么机制？
3. 哪几条其实是同一件事的不同说法，应该合并？

### Q-A1-06 · 换脚分成四段，和教学里的分法一致吗？

**影响**：`TEC-CON-SWAP-003` 的三阶段字段、
`FAULT-SWAP-DROP-021` 的「掉在哪一段」分诊表。

**背景**：我们把换脚拆成 **卸载旧脚 → 旧脚离开 → 新脚落位 → 加载新脚** 四段，
并主张「新手通常只做中间两段」。这个分法是我们为了让每一段都能对应到
一个可观察量而设计的，不是从任何教材里抄的。

**问题**：

1. 教学里通常怎么分？有没有更常用的说法？
2. 「新手只做中间两段」这个判断你同意吗？
3. 如果要在墙上只提醒一句，你会提醒哪一段？

### Q-A1-07 · 小跳换脚的安全提示是不是写过头了？

**影响**：`TEC-CON-SWAP-003` 与 `FAULT-SWAP-DROP-021` 的 `safety`。

**背景**：我们写了两条与小跳换脚有关的安全边界：

> 小跳换脚有一个双脚离墙的瞬间，落回时踝关节和脚趾承受冲击；
> 脚点小、鞋底打滑或热身不足时不要用小跳。

> 反复失败的小跳换脚会累计踝关节冲击，连续两次没换成应当下墙调整解法。

这两条都是**我们自己推的**，没有损伤研究支撑，也没有教练背书。
写保守的代价是可能吓住用户，让他们不敢用一个其实很常用的技巧。

**问题**：

1. 这两条是过度谨慎，还是合理？
2. 「连续两次没换成就下墙」这个阈值有没有更合适的说法？
3. 抱石高度上，小跳换脚失败真正的风险是踝关节，还是**落地姿势**？
