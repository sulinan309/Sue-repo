## 这次发生了什么

和 [CASE-2608-002](CASE-2608-002.md) 是同一段素材（`82a02e78.mp4`，
`annotator/out7`），但看的是另一件事：那次看的是高脚发力，
这次看的是**发力之后的两次换脚点**。

两段都是左脚离开 0.43 秒，期间右脚**始终**在点上（接触率 1.00）。
两段里两条手臂都弯着——第一段右肘中位 108.3°，第二段 92.5° 和一个 20.3°。

**如果只看肘角，这里会报出一条「换脚时挂在手上」。那是错的。**
同样这两段里，重心分别上升了 0.087 和 0.173 倍躯干长。
手固定在岩点上、身体往上走时，肩会靠近手，**手臂必然弯曲**——
弯曲是身体上升的结果，不是挂着的证据。

## 为什么值得留档

### 一、它是「单个量不能脱离语境判断」的样本

这条教训在管线里已经被两次实测推翻过（见 `annotator/README.md`）：

1. 手点低于肩时，直臂根本不是选项，肘角是几何决定的；
2. 手固定、身体上升时，肘角必然变小，那是进展。

本例属于第二类，而且**第一类在这里不成立**——两段里最高的手都在肩以上
（+0.563 / +0.571），几何上直臂本来是个可选项。
两个原因必须分开验证，不能合并成一句「屈臂就是不好」。

评测意义：这两段是**易误判样本**。系统在它们上面保持沉默才算对；
报出「屈臂」就算错，哪怕报出来的肘角数字是准的。

### 二、它给出了 A1 主题的一个硬边界

**这两段都不是同点换脚。** 移动脚相对另一侧踝的净位移是 0.32 和 0.97 倍躯干长，
第二段结束时左踝已经在右踝**上方** 1.11 倍躯干长处——左脚去了一个明显更高的位置。

更要紧的是：**管线自己分不出这件事**。
本段素材全片脚与岩点的关联率是 **0**（左脚 0/29、右脚 0/77 接触帧），
而手是 19/20 和 69/70；另一段素材 `out5` 同样是 0/199 与 1/210。
没有脚—岩点关联，
「同点换脚」「换到另一个点」「脚脱落」在管线眼里是同一件事：某只脚离开了一段时间。

所以 [TEC-CON-SWAP-003](../techniques/TEC-CON-SWAP-003.md) 里
关于同点换脚的部分，**目前没有任何内部数据支持**，
现有素材也无法用来验证。要补的是素材，不是算法参数。

### 三、一个还没结论的疑点

第二段的左肘角中位是 **20.3°**。人的肘关节屈到底一般也到不了这个角度，
这个数很可能是投影伪影——左肘整段可信率只有 0.39。
但 `joint_reliability` 在这一段里判它「可测」了。

这条写在 `expert_notes` 里，**是研究专家的推断，不是管线结论**，
需要工程复核。它不影响本单元的其余结论：
即使把左肘那一条整段丢掉，右肘的 108.3° 和 92.5° 仍然成立，
「重心在升」的结论也来自重心轨迹，与肘角无关。

## 怎么复现

```bash
python3 climbing-kb/tools/swap_segments.py annotator/out7
```

该脚本从 `keypoints.npz` 与 `evidence.jsonl` 重建姿态帧，
调用管线自己的 `climbanno.posture.detect_bent_adjust`，
只把两个**报警阈值**放开（`RISING`、`HAND_HIGH`），
好让被过滤掉的段本身连同它的实测量一起打印出来。
段的划分、肘角、重心上升、手相对肩高度全部由管线原函数计算，未做任何替代实现。

**注意**：`annotator/out*` 不在 git 跟踪范围内（见 `annotator/.gitignore`），
qa 已把 `out5`/`out7` 的四个数据文件固化到 `qa/fixtures/`。
上面这条命令换成 `qa/fixtures/out7` 同样能跑。
