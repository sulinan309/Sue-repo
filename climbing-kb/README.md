## 快速上手

```bash
pip install pyyaml

python3 tools/validate.py    # 校验结构完整性（每次提交前跑）
python3 tools/build.py       # 编译成 dist/kb.json 供检索
python3 tools/query.py 脚滑   # 按用户的一句话检索
python3 tools/perception_audit.py   # 审计知识库对感知能力的需求
python3 tools/swap_segments.py annotator/out7   # 取回脚离点段的管线实测量（案例单元用）
```

看一条完整的解题链——这是产品给建议时实际走的路径：

```bash
python3 tools/query.py --chain FAULT-FOOT-SLIP-001
```

输出会依次给出：用户会怎么说 → 视频里能看见什么 → **4 个候选解释（各带证据要求）**
→ 局部提示 → 现实任务及完成证据 → 背后的物理 → 安全边界。

## 怎么组织的

知识库同时保留两条轴，在技巧单元上交汇：

```
轴一（原理→动作）   物理原理 → 动作原则 → 技巧 → 手脚接触
轴二（问题→行动）   用户的一句话 → 卡点 → 多个候选解释 → 提示 → 任务
```

**轴二是产品实际走的路径。** 用户不会说「我力矩失衡」，他会说「我一松手就被转开」。
所以卡点单元是入口，技巧单元是解释层。

每个知识单元是一个 Markdown 文件：YAML front matter 承载结构化字段供脚本校验和编译，
文件体承载给人看的解释和科普素材。专家用普通编辑器就能改，不需要后台；
版本和修改原因由 git 承载。

## 三条贯穿全库的硬规则

**1. 卡点必须给多个候选解释。**
每个卡点单元至少 2 个候选解释，各自标明需要什么证据才能成立。
`validate.py` 强制这一条。

理由：同一个「动态没抓住」有五种机制，解法完全不同。
合成一句「多练握力」，用户练很久也不会好。

**2. 证据等级决定表达强度。**
`可确认事实 / 研究证据 / 专家共识 / 专家假设 / 证据不足` 五级。
一个单元只标一个等级，**取该单元内最弱的一条主张**。
标「专家假设」的内容不进入产品自动输出。

**3. 物理公式解释关系，不生成人体数值。**
可以说「髋离墙越远手越累」，不能说「你的重心偏离了 12 厘米」。
单机位手机视频给不出后者。

## 当前的硬阻塞

**70 个单元全部是 `review.status: pending`。**

按《知识库规范》06 节，只有走完事实审核、攀岩审核、教学审核三关的单元
才能进入产品自动输出。这是目前唯一挡住下游的事情——内容本身已经写完了。

按 `project/02-决策记录.md` 的 **D-003**，项目已决定暂不引入外部真人攀岩专家，
所以这个阻塞**短期内不会解除**，队列会持续堆积。
具体的、有分歧或没有依据的问题收在 [待专家问题.md](待专家问题.md)，
写成可以直接照着答的形式，以便复核资源到位时能一次性处理。

第二个阻塞是来源可达性：本环境的出站策略拦截 `pubmed` / `pmc` / `thebmc.co.uk`
等域名，`WebFetch` 打不开原文，只有搜索工具可用。
结果是新一轮的外部来源**全部停在「候选」**，无法推进到「登记」，
也就无法支撑 `研究证据` 等级。详见
[sources/2026-08-换脚与支撑交接-来源检索.md](sources/2026-08-换脚与支撑交接-来源检索.md)。

其余待定问题见 [docs/02-建设路线.md](docs/02-建设路线.md) 第 04 节。
