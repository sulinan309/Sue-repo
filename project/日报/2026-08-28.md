**R-001：零个知识单元通过真人攀岩专家复核，这不是四个 agent 能自己解决的问题，需要外部真人专家。**

复核者必须是真人攀岩专家。按 `project/README.md` 的定义，真人攀岩专家是"按需介入的外部资源，不是常驻角色"，不在 research / product / engineer / pm 四个 agent 的能力范围内。这件事决定了后续所有工作的价值上限：无论知识库单元数扩到多少、评测集补到多少例、MVP 做得多完整，只要复核这一步没人做，产出就停留在"专家假设"级别，进不了"允许自动输出"的门槛。也就是说，其余三条线现在做的工作，其最终价值都悬在这一步能不能被推动上。

需要人决定"怎么拿到外部真人专家资源"，选项与代价如下：

- **选项 A · 收窄送审范围，先换第一次复核**：从 66 个单元里选出优先级最高的一批（如高频卡点 + 核心技巧）先送审，而不是等全部单元都齐了再送。
  代价：知识库对外覆盖面短期不扩大；后续单元还要分批再占用专家时间；但返工范围被限制在小而精的核心资产上，风险可控。

- **选项 B · 暂不引入外部专家，按当前节奏继续扩充**（即不作为的默认路径）：知识单元、评测集、MVP 都先往前推，复核放到后面统一处理。
  代价：与风险清单 R-001 描述的一致——所有下游产出（评测集的"正确判断"标准、MVP 的自动输出结论、工程验证的可信度）都建立在"专家假设"上；一旦复核阶段被推翻或大改，返工覆盖知识库 + 评测集 + MVP 判断逻辑，返工量不可控。本质是把风险往后堆，堆得越久代价越大。

- **选项 C · 主动联系/引入真人攀岩专家资源**（教练、资深攀岩者等），并定下复核方式（远程审文本，还是要看视频对比）与节奏。这是唯一能实质缓解 R-001 的路径，但完全在四个 agent 能力范围之外。
  代价：需要人力、时间、可能的报酬去找到并对接资源；找到之前，A、B 都只是缓解节奏或延后风险，不解决"无人背书"的根本问题。

A 和 C 不互斥，可以同时推进；B 是没人推动 A/C 时的默认状态。要不要现在启动外部专家资源的对接、找谁、什么节奏，需要人来决定，这里不替项目拍板。
