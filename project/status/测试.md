### 2 · 数值基线不依赖会消失的东西

`qa/用例/qalib.py::load_nv()` 是 `anchor.load()` 摘掉读帧那一段的版本，
算法全部 import 真模块。趁原始视频还在，做了一次逐位取证
（`t00`，50 项断言全过）：`t0` / `t_end` / `n` / `fps` 完全相同，
`dx` / `dy` / `torso` / `ax` / `ay` 五条序列最大绝对差 **0.0**。
视频消失后 `t00` 自动 SKIP，其余 9 个文件照跑。

工程师给的已知正确值**全部复现**：
站起来了 T0=0.97s 横向偏 0.25 +0.8s +0.36 +2.0s **+0.99**；
没站起来 T0=2.10s 横向偏 0.40 +0.8s **−0.53** +2.0s **−0.50**；
最小间距 **0.37**，交叉帧 `[]`，两侧各 57 帧同号。
`tools/validate.py` 退出码 0。

基线自己也做了灵敏度自检：T0 后重心上移 3px（躯干长的 1.6%）→ 哈希与上屏数字都变；
整幅平移 7px → 数字不变（承重踝参考点该抵消镜头平移）。
拿 `annotator/out6`（旧版管线）跑同一套计算，得到 0.39 / **−0.38** / 0.26，
与 README 记录的那次事故完全一致——**基线能把 −0.50 和 −0.38 区分开。**

## 被阻塞的验证

**这一段请项目经理如实转达，它不是「还没写」，是当前约束下写不了。**

1. **整个感知前端没有回归保护**。原始视频不进 git（人的决定），
   所以 `pose.py`（ROI 追踪/检出率）、`holds.py`（岩点+墙面单应）、
   `contact.py`（接触判定）三层完全没测。
   **后果说清楚**：MediaPipe 换版本、ROI 策略被改坏、接触阈值调错，
   本套测试一条都不会响——因为它读的是固化下来的旧 npz。
2. **`drive.*` 只测到图像坐标**，管线口径要等 D-006。
3. **渲染层一个像素都没测**（需要真帧）。测的是印在画面上的数字，不是画面。
4. **评测集只有 3 条且同源**，三类各 1 条，`review.status` 全是 pending。
   `eval_expect` 是自然语言，`t09` 的断言是它的一种翻译，**需要研究专家复核翻译**。
5. **验收标准逐条对照没做**——`product/` 下还没有带可测数字的验收标准。
6. `detect_bent_adjust()` 只验证了「不误报」，**没验证「该报的时候会报」**。

完整的「本次没有验证什么」在 `qa/报告/2026-08-28.md`，共 8 条。
