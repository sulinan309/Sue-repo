## 一 · D-007：`review.py` 在「结尾即最高点」的素材上崩溃

### 改了什么

`annotator/review.py`

- 新增 `_seg_pct()` / `_seg_med()`：**可用样本不足就返回 `None`（该项不可用），
  绝不返回 0。** 空段不再进 `np.nanmean`，也就不再有 NaN 进 `round()`。
- `posture()` 每段额外带上 `帧数` / `不可用项` / `不可用原因`，
  「为什么没有数」也是从代码里算出来的，不是打印层写死的话。
- 打印层：`None` 印成「不可用」，并在表下方明写没有可用段的原因。
- 分段本身没动（`peak` 切上攀/下攀），按缺陷清单的建议保留。

### 复现 → 修复（同一条命令）

```bash
# 修复前
$ python3 annotator/review.py qa/fixtures/out7/evidence.jsonl ; echo $?

  File "annotator/review.py", line 134, in <dictcomp>
    "双肘同时弯曲": round(float(np.nanmean(both_bent[sl])) * 100),
ValueError: cannot convert float NaN to integer
1

# 修复后
$ python3 annotator/review.py qa/fixtures/out7/evidence.jsonl ; echo $?
0            （stderr 0 字节，RuntimeWarning 一并消失）
```

修复后 out7 的那张表：

```

  上攀               3.2           65%           35%            1%          0.58           78%
  下攀               0.0           不可用           不可用           不可用           不可用           不可用

  没有可用的下攀段：长度为 0 帧，髋部最高点就是最后一帧。
  该段 5 项姿态几何指标记为不可用，**不是 0%**——0% 会被当成一次真实观测。
```

### 验证「只修崩溃，不动数字」

1. **out5 端到端输出逐字节不变**，且与回归基线里记的哈希一致：


2. **磁盘上全部 8 个产物目录逐项对照旧口径**（把旧表达式原样跑一遍再比）：

| 目录 | 旧口径 | 与新口径 |
|---|---|---|
| `qa/fixtures/out5`、`annotator/out2/3/4/5/6` | 能跑 | **6 个目录 × 2 段 × 6 项全部相同** |
| `qa/fixtures/out7`、`annotator/out7` | 崩（Mean of empty slice） | 新口径退出 0，下攀段标为不可用 |

3. `review.py` 在 out2 / out3 / out6 上端到端退出码 0、stderr 0 字节、行数 42
   （与修改前同为 42 行）。

### 关于「每一段成功的尝试都长这样」——测试的判断成不成立

**根因判断完全成立，但「常态」的描述只对了三分之一，而漏掉的那部分更危险。**

- **触发条件精确**：`slice(0, peak+1)` 永远非空，`slice(peak+1, n)` 当且仅当
  `peak == n-1` 时为空。out7 `peak=94 / n=95`，确认。
- **机制成立**：剪到动作完成为止的片段，结尾就是全片最高处。
- **但「峰值恰好落在末帧」是掷硬币**：out7 最后 3 帧的髋高彼此相差 **< 1.0px**，
  最后 5 帧总跨度 **3.1px**，而全片逐帧位移中位是 **2.28px**——
  谁是最高点由亚像素噪声决定。
- **没崩的那几面更糟**：把 out7 末帧髋高抬 **5px**（小于关键点自身抖动），
  `peak` 退到 93、下攀段变成 **1 帧**，旧代码**不崩**，改成打印

  ```
  旧口径（1 帧）：双肘同时弯曲 100%   至少一条直臂 0%   宽站姿 0%   站姿宽度中位 0.63
  ```

  这正是「NaN 换 0 会造出一个静默错误」的同一形状，只是它自己就会发生。
  合成素材复现脚本的输入是 `qa/fixtures/out7/keypoints.npz` + `hip[-1,1] += 5`。

- **样本量交代清楚**：手上只有 **1 段**成功素材（out7），
  「每一段成功的尝试」这句话我验证不了，**验证的是机制不是频率**。

所以修法不是「空段特判」，而是**按可用样本量拦**：
`SEG_MIN_S = 0.5s`（30fps 下 15 帧），少于它一律不给百分比——
n 帧算出的百分比分辨率只有 100/n。0 帧和 1 帧走同一条路。

## 二 · D-001：陈旧输出目录只告警不阻断

按测试给的分界线实现：**会写进知识库的路径硬失败，只出图的路径告警。**

### 改了什么

`annotator/climbanno/anchor.py`

- `check_fresh()` **返回缺失字段列表**（空列表 = 新鲜），告警照旧发。
  调用方第一次能在程序里判断目录新不新鲜。
- 新增 `require_fresh(outdir, why)`：陈旧就 `SystemExit`，中止信息说清
  「停下来的是哪一步」。`anchor.load()` **不调用它**（探索性路径保持告警）。

`annotator/make_case.py`

- 两条写 `kb/cases/*.md` 的路径（`--update-measured` 和草拟新单元）都过
  `_fresh_gate()`。
- 逃生口 `--allow-stale`：放行，但**必须留痕**——往案例的 `versions:` 块写
  `source_stale: [...]`；换回新鲜目录重算时痕迹自动摘掉（痕迹描述的是
  `measured` 的来源）。没有 `versions` 块就拒绝写（不写好过写一个看不出来源的数）。
