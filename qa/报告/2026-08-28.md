### 3 · 关节可信度与拒答（`t05`）

**可信率能复现**：从 npz 重算 `pose.reliability()` 与 `reliable_windows()`，
out5 得 0.926、out7 得 0.853，可分析区间 `[[0.0,0.87],[1.07,1.5],[2.17,8.6]]`

**判据真的会判不可信**：合成骨架，把左前臂 / 右腿的投影压缩，
`joint_reliability()` 与 `drive._unreliable()` 都把该侧标出来，

fixtures 上的关节可信率也存了快照：

```
out5  L_ELBOW 0.260  R_ELBOW 0.903  L_KNEE 0.961  R_KNEE 0.787
out7  L_ELBOW 0.389  R_ELBOW 0.842  L_KNEE 0.789  R_KNEE 0.516
```

### 4 · 基线对比（`t06`）

`review.py` 的拦截逻辑测下来是**结实的**：

- README 里那两条候选的判定原样复现：
  15/20 对基线 57% → z=1.63 p=0.052「样本不足，仅为倾向」；
  12/17 对基线 78% → z=−0.74 p=0.77「与基线无实质差异，不构成发现」。
- **同一个 71%，基线换成 30% 就变成「可确认事实」**——
  证明拦截依据是基线，不是「百分比看着高不高」。
- 网格扫描 **990 组** (k, n, baseline)：
  「可确认事实」当且仅当 p<0.05，判定文案与 p 的三档划分零偏差。
- 退化输入（n=0、基线 0、基线 1）不会伪装成发现：z 归零、p 取 1.0、判「证据不足」。
- 端到端跑 out5，每条候选都带「基线 / z= / p=」三样，一样不缺。

顺带查出 **D-007（高）**：

```
$ cd annotator && python3 review.py ../qa/fixtures/out7/evidence.jsonl
ValueError: cannot convert float NaN to integer      (review.py:134)
$ echo $?
1
```

根因：`posture()` 用髋部最高帧切上攀/下攀两段，最高点落在最后一帧时
下攀段长度为 0，`np.nanmean(空)` 得 NaN。out7 的 `peak=94`、`n=95`。
**每一段剪到动作完成为止的成功尝试都长这样**——`review.py` 在最该分析的
那类素材上不可用。好在它崩了，没有静默给出错数字。

### 5 · 字幕极性（`t07`）

合成图，不需要真视频：

- 黑底白字与白底黑字的笔画覆盖率 **0.1618 / 0.1608**，差 0.001——
  梯度取模与极性无关；空白底板 <0.005。
- 同一句话在两种极性下的字模差 **< 0.04**（去重阈值），判为同一句；
  两句不同的话在两种极性下差都 **> 0.04**，不会被去重丢掉。
- 对照：朴素「亮＝字」实现在白底上覆盖率 **0.869**（黑底 0.108，差 8 倍）——
  **抓到的是整块底板**。低对比度白底（笔画 205、底板 250，都在阈值同侧）时
  朴素字模变成常量 1，任何两句话完全相同；梯度字模仍分得开。
- 端到端：4 句话的白底 / 黑底 / 低对比度白底三段素材，
  `extract()` 都抽出 4 条；把 `text_mask` 换成朴素实现，
  同一段素材**塌成 1 条**——这就是「丢了 48–64 秒」的形状。
- `find_band()` 在两种极性下定位到**同一条**字幕条。

| 岩点与墙面 | `holds.py` 的 `detect_stable` | 同上；且逐帧单应 `Hs` 根本没写进任何文件（D-006） |
| 接触判定 | `contact.py` 的 `analyse` / `stabilise` | 同上，`evidence.jsonl` 是它的输出 |

**具体后果，说清楚**：如果 MediaPipe 换了版本、ROI 重捕获策略被改坏、
接触阈值被调错，**本套测试一条都不会响**。检出率从 100% 掉到 46.7% 也照样全绿，
因为测试读的是固化下来的旧 npz。这是这套基线最大的洞，
它不是「还没写」，是**在当前约束下写不了**。

### 二、`drive.*` 测的是图像坐标，不是管线口径

管线跑三个检测器时都带着 `wall_H`。测试只能在图像坐标下跑它们。
差多少已经量过：同一段停滞 −0.03（墙面）vs −0.24（图像）。
所以 `t05` 里那些 `detect_stalls` / `detect_rises` 的行为断言，
**验证的是拒答逻辑与分段边界，不是管线真正输出的数值**。
`summary.json` 里的 `stalls` / `rises` / `drives` 数值本轮**只被当成给定值核对**
（`t04` 检查它们与案例 `measured` 一致），**没有被重算验证**。
D-006 修掉之后这一条才能补上。

### 三、渲染层一个像素都没测

`render.py` / `viz.py` / `compare.py` 与 `card.py` 的画面部分需要真帧。
本轮测的是它们**印在画面上的数字**（`anchor.py` 那一层），
不测任何视觉产物。「裁切框会不会把脑袋切掉」「两行是不是同一个比例尺」
「教练卡片有没有压住动作」——都不在本套测试内。

### 四、拒答场景没测全

已覆盖：关节可信度过低、输出目录陈旧、样本不足/与基线无差异。
**没覆盖**：

- **非攀爬内容**（`annotate.py` 的亮度突变告警）——需要帧
- **可用帧数不足**（`compare.py` 的「从 T0 起只有 X s，不足 2.0s」退出路径）
- **轨迹交叉时拒绝上屏**（`compare.py` main 里那条断言）——
  `t02` 测了「当前数据不交叉」，没测「交叉时确实会拒绝」

### 五、评测集验收：报了，但样本只有 3 条且同源

研究专家在本轮工作期间给三条案例都补上了 `eval_class` 与 `eval_expect`，
于是 `t09` 当场把它们翻成了可执行断言。**分类通过率（易误判单独报）**：

```
评测集分类通过率（易误判单独报，不并入总数）
──────────────────────────────────────────────────────────────
  成功    1/1   CASE-2608-002✓
  失败    1/1   CASE-2608-001✓
  易误判   1/1   CASE-2608-003✓
──────────────────────────────────────────────────────────────
```

**这个 3/3 几乎不能说明任何事，理由要写清楚**：

1. **样本量 3 条，且全部来自同一个人、同一面墙、两段素材**
   （out5 一段、out7 一段，其中 out7 被两条案例共用）。
   通过率不能外推到别的攀岩者、机位或岩馆。
2. 三条全部 `review.status: pending`——**评测集本身还没过审**。
3. `eval_expect` 是自然语言，`t09` 里的断言是它的**一种翻译**。
   翻译对不对要研究专家复核；断言描述里逐条写了翻译成了什么，就是为了让人能核。
4. 验收跑的是**图像坐标**下的检测器（`wall_H` 没落盘，D-006），
   `stalls` / `rises` / 教练卡片取自 `summary.json` 即管线当时的真实输出，
   没有重算。

易误判那条查得比另外两条实：`CASE-2608-003` 记录的正是「管线曾把进展
报成问题」的两段。`t09` 用**正常阈值**跑 `posture.detect_bent_adjust()`
（案例的 `measured` 是研究专家把 RISING / HAND_HIGH 放开为「全部报告」跑的，
那是取材不是产品行为，两条路径必须分开），结果**一条屈臂都不报**；
同时确认对用户说的话里没有「换脚 / 同点 / 同一个岩点」字样，
而脚与岩点的关联率实测确实是 0（左脚 0/29、右脚 0/77）——
**它没有声称自己看见了看不见的东西。**

### 六、验收标准逐条对照：没做

`product/` 下尚无带可测数字的验收标准，无从对照。

### 七、其他明确没测的

- `detect_bent_adjust()` 的两条前置条件（「手高于肩」且「重心无上升」）——
  `t09` 测了它在 out5 / out7 上**不误报**，但**没有测它该报的时候会报**：
  手里没有一段「手高于肩且重心没上升」的真实素材，也没有造合成用例。
  这条指标被数据推翻过两次，只验证「不误报」是半边
- `posture.py` 的四格姿态分类、`coach.py` 的卡片组装与优先级
- `holds.json` 的内容（本轮只核对了它的存在与哈希，没有验证任何岩点坐标）
- 性能、耗时、内存
- 依赖版本漂移（numpy 2.4.6 / opencv 5.0.0 / PyYAML 6.0.1 下的结果，
  换版本会不会变，没测）

### 八、一件本轮观察到但没法回溯的事

知识库在本轮工作期间从 66 个单元长到 70 个（研究专家在并行工作）。
17:08 左右曾出现 `kb/` 有 70 个而 `dist/kb.json` 只有 66 个的状态，
17:20 再看已经同步。**那段时间里任何一次 `annotate.py` 都会对着旧知识库
出能力对照，而且不会报错。** 记为 D-009，并已在 `t08` 做成硬断言。
但**中间那段窗口的产物无法回溯判断**——因为产物不记知识库版本（D-008）。
