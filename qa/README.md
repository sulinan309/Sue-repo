# 测试

> 由 `qa` agent 独占写。其余角色只读。

## 怎么跑

```bash
./qa/用例/run.sh              # 全部，退出码 0/1
./qa/用例/run.sh t02 t05      # 只跑匹配的
./qa/用例/run.sh --bless      # 重建 qa/回归基线/ 下的快照
```

只需 numpy / opencv / PyYAML。**不需要 mediapipe，也不需要任何视频。**

## 这里为什么不放通用测试模板

这个项目的失败模式不是崩溃，是**静默地给出一个看起来合理的错数字**。
`annotator/README.md` 里的每一条教训都是这样发生的：程序正常退出、
输出格式正确、数字看着合理——但那个数字是错的。

所以测试的重心在于**检测无声的变化与无声的错误**，而不是覆盖率数字：

- 同一输入换个输出目录，结论从 −0.50 变 −0.38，两次都不报错
- 姿态检出率 100%、可信率 85%，在噪声上算的结论和在信号上算的长得一样
- 「同步率 71%」看着像发现，直到有人去跑基线，发现基线是 78%

## 缺陷由谁修

**测试不改 `annotator/`。** 发现问题写进 `缺陷清单.md`，工程师修。
这是为了保住独立性——写代码的人不该是唯一判断它对不对的人。
