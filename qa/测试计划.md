# 测试计划

> 版本 v1（T-006 建立）· 2026-08-28 · 由 `qa` 独占写

## 一句话

这个项目的失败模式不是崩溃，是**静默地给出一个看起来合理的错数字**。
所以测试的重心是**检测无声的变化与无声的错误**，不是覆盖率。
一个只能发现崩溃的测试套件，对这个项目几乎没有价值。

## 跑法

```bash
./qa/用例/run.sh              # 全部，退出码 0/1
./qa/用例/run.sh t02 t05      # 只跑匹配的
./qa/用例/run.sh --bless      # 重建 qa/回归基线/ 下的快照
```

不依赖 pytest（本机 `python3` 里没有），只需 numpy / opencv / PyYAML。
不需要 mediapipe，也**不需要任何视频**。

## 优先级与当前覆盖

按 `.claude/agents/qa.md` 的五类排。

### P0 · 回归基线（最高）

同样的输入必须产出同样的数字。

| 用例 | 测什么 | 手段 |
|---|---|---|
| `t01` | fixtures 没被动过 | 8 个文件的 SHA-256 + 结构不变量 |
| `t02` | `anchor.py` 的数值行为 | 5 条逐帧序列哈希 + 上屏数字 + 灵敏度自检 |
| `t05` | 可信度判据的数值行为 | 4 个关节可信率 + 2 条腿压缩率快照 |
| `t06` | `review.py` 端到端输出 | stdout 哈希 + 条数 |
| `t00` | 无视频加载器 == 真加载器 | 视频在时逐位比对，不在时 SKIP |

**基线只依赖 `qa/fixtures/`。** 原始视频是容器级的、会消失，而且人已决定
不进 git（可识别的真人影像）。`qalib.load_nv()` 把 `anchor.load()` 的读帧段
摘掉，算法全部 import 真模块，2026-08-28 已用真视频逐位交叉验证过（差 0.0）。

### P1 · 拒答测试

系统在该说「我看不准」的时候有没有说。**能正确拒答和能正确回答同样重要。**

| 场景 | 用例 | 现状 |
|---|---|---|
| 关节可信度过低 | `t05` | 三个检测器在 `reliable` 全 False 时都不出结论；停滞段可信率 <40% 被丢 |
| 输出目录陈旧 | `t03` | 会告警，但**只 print 到 stderr，不中断**（D-001） |
| 样本不足 / 与基线无差异 | `t06` | `finding()` 判「证据不足」，p≥0.05 永不给「可确认事实」 |
| 非攀爬内容 | — | **未覆盖**，需要视频（见下） |
| 可用帧数不足 | 部分 | `compare.py` 的「不足 2.0s 直接退出」未单独测 |

### P2 · 口径一致性

同一个量在知识库、产物、文档里必须是同一个数。这类核对必须是脚本，不能靠人眼。

| 用例 | 核对什么 |
|---|---|
| `t04` | `CASE-2608-001/002` 的 `measured` 与 `make_case` 重算逐项相同（直接调真函数，只换掉读视频那步） |
| `t04` | 案例的检出率/可信率/可分析区间与 `summary.json` 同源 |
| `t04` | `facts` 与正文里的叙述数字回指 `measured` |
| `t05` | `pose_reliable_rate` / `analyzable_windows` 能从 npz 重算出来 |
| `t08` | 产品说的每一句 hint 都在知识库 `hints` 里逐字存在 |
| `t08` | `kb_link.EMITTED` 的 8 条 observable 逐字存在 |
| `t08` | `dist/kb.json` 与 `kb/*.md` 的 hints / observables 一致 |
| `t09` | `CASE-2608-003` 声称的岩点关联率与 `evidence.jsonl` 重算一致 |

### P3 · 已知静默失败的复现

`annotator/README.md` 里每一条教训都变成一条会响的检查。

| 历史事故 | 用例 | 形式 |
|---|---|---|
| 换输出目录，−0.50 变 −0.38 | `t03` | 缺字段的 summary 必须告警且点名字段 |
| 100% 检出率 / 85% 可信率 | `t05` | 可信率可复现；不可信时下游必须闭嘴 |
| 「同步 71%」像发现，基线 78% | `t06` | 复现原数字并断言判「不构成发现」；换低基线则变成发现 |
| 屈臂被误报为可优化项 | `t09` | 正常阈值下 out5 / out7 都不报屈臂（`CASE-2608-003` 记的正是那两段）；**「该报时会不会报」未测** |
| 字幕丢 48–64 秒 | `t07` | 两种极性都出笔画；朴素亮度实现在白底上塌成常量 |

### P4 · 评测集验收

`t09` 把每条案例的 `eval_expect` 翻成可执行断言，**分类报通过率，易误判单独报**。
当前：成功 1/1、失败 1/1、**易误判 1/1**。

**这个 3/3 几乎不能说明任何事**：3 条案例全部来自同一个人、同一面墙、
两段素材，且全部 `review.status: pending`。通过率不能外推。
需要研究专家补不同人 / 不同机位 / 不同墙的样本。

### P5 · 验收标准逐条对照

**本轮没有做。** `product/` 下尚无带可测数字的验收标准。
每条标准都要能写成一个测试，写不成的要反馈给产品经理。

## 明确不测什么

这一栏和上面一样重要。

| 不测 | 为什么 |
|---|---|
| **`pose.py` 的检出率与 ROI 追踪** | 输入是 BGR 帧，视频不进 git。npz 是它的输出，测试只能当给定值 |
| **`holds.py` 的岩点检测与墙面单应** | 同上；且 `Hs` 根本没写进任何产物（D-006） |
| **`contact.py` 的接触判定** | 同上，`evidence.jsonl` 是它的输出 |
| **`drive.*` 的管线口径** | 管线带 `wall_H` 跑，测试只能在图像坐标跑。同一段停滞 −0.03 vs −0.24 |
| **渲染层的画面**（`render.py` / `viz.py` / 卡片与对比视频的像素） | 需要真帧。测的是印在上面的数字，不是像素 |
| **非攀爬内容告警** | `annotate.py` 的亮度突变检测需要帧 |
| **模型与依赖版本漂移** | MediaPipe 换版本 → npz 变 → 但测试读旧 npz，一条都不会响 |
| 覆盖率数字 | 这个项目的风险不在未执行的分支，在执行了并给出错数的分支 |
| 性能与耗时 | 当前不是约束 |
| 文风、措辞、排版 | 归产品与设计 |

## 已知缺陷不让套件变红

已知缺陷用 `XFAIL` 记录：**不算失败**，但每轮打印出来。
一旦某条已知缺陷的行为变了（`XPASS`），套件**故意判失败**——
逼着有人回来更新 `qa/缺陷清单.md`。两个方向都会响。
